Code-level verification that the MP-1..MP-9 fixes from
`Docs/CODE_REVIEW_2026-10-29.md` (claimed landed in Phase 7.5) are actually in
`gigad1k/mimo-dev`, plus the Phase 9 authority audit (server owns treatment,

client-reachable entry point (RPC / interact / input) to its server-side
validation. Two-instance PIE with humans is still pending (NEEDS_ALI #5);

## Late-join / reconnect

- Replicated shift surface: `WeatherSeverity`, `ShiftState`, `ShiftTimeRemaining`,
  `Quota`, `OnTimeDepartures`, `LateDepartures`, `Money`, `Deductions`,
  `bShiftPassed`, `DispatchFeed` (`HoldoverGameState.cpp:277-290`) — a late joiner
  gets the full ledger snapshot. Aircraft/section/tank/playerstate all replicate.
- **Gap G-5:** `LastShiftDuration` is not replicated (`HoldoverGameState.h:156`) —
  a late joiner computing elapsed = duration − remaining reads the local default
  (120 s). Also `PayPerOnTimeDeparture` / `LateDepartureDeduction` are
  `EditDefaultsOnly` (not replicated) — HUD values would be wrong if tuned
  differently from the C++ default.
- Reconnect = fresh join in the session design (no seamless reconnect promised);
  a reconnecting player gets a fresh character and the replicated world state —
  acceptable per plan ("test late join/reconnect only if supported").

## What this audit does NOT claim

- No two-machine / two-PIE-window session has been played (NEEDS_ALI #5). The
  code paths are verified; perceived behaviour on a live client seat is not.
- Packet-loss ordering effects (unreliable boom RPC reordering, `COND_SkipOwner`
  under loss) are covered by the rate clamp + owner prediction design but not
  packet-level tested in automation. The manual net-emulation checklist
  (`PktLag=120 PktLoss=5`, `Docs/TESTING.md`) remains the live check.
