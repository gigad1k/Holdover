# HOLDOVER — Code & Design Review (2026-10-29)

**Scope:** full `Source/Holdover` module (committed + the uncommitted Phase 7 working-tree diff), `Docs/`, `Config/`, `Tools/`, `Holdover.uproject`, tests.
**Method:** multi-agent review (gameplay sim, player/truck, UI/audio, networking, tests/tooling, design) with every high-severity claim adversarially re-verified against the actual code before inclusion. One claimed high issue was refuted during verification and is downgraded (see PROC-2).
**State at review:** Phase 7 of 10 complete but uncommitted; `main` at `a6d00e2` (phase-6).

---

## Verdict

The idea is strong and the engineering discipline is unusually good, but the build is currently a competent **single-player** logistics prototype wearing a co-op comedy pitch. The holdover clock (timer starts only when the work is done, burns faster in worse weather) is a genuinely original hook. The architecture — deterministic server-side simulation, single testable update path, clean clamping, honest docs — is the right chassis. The two things the store page promises, **co-op** and **comedy**, are the two things not in the build: several core systems silently work only for the listen-server host, and the comedy exists as pitch text plus one word ("RESTRUCTURED.").

**Root cause of the multiplayer bugs:** everything was verified from the host's seat, where client == server. None of the MP issues below are visible in single-process listen-server PIE play as the host.

## What is genuinely strong (keep doing this)

- Correct authority skeleton: client traces → Server RPC → server re-validates range/rules (`HoldoverCharacter.cpp:265`, `HoldoverSprayComponent.cpp:172`).
- `SimulateTreatment(dt, weather)` is world-free and test-covered; 6 deterministic automation tests pass.
- Numeric hygiene throughout (clamps, dt guards, divide-by-zero guards). No unclamped-value bugs found.
- LFS/.gitignore correct; per-phase CHANGELOG with evidence; KNOWN_ISSUES records root causes.
- "RESTRUCTURED." proves the team can write the tone — it just appears exactly once.

## A. Multiplayer correctness — VERIFIED, ship-blockers (MP-1 .. MP-9)

All confirmed by independent re-verification against the code. Scenario: listen server + 1 remote client.

- **MP-1 — Remote clients can never spray Type IV.** `ActiveFluidType` is flipped locally on Q (`HoldoverCharacter.cpp:188-194` → `HoldoverSprayComponent.cpp:41`) with no Server RPC and is not replicated (`GetLifetimeReplicatedProps`, cpp:190-195, registers only the two tanks). `ServerSpray` applies the **server's** copy, permanently Type I for remote players: their HUD says TYPE IV while the server cleans and drains the wrong tank. Half the core loop is host-only. *Fix: route the toggle through a Server RPC and replicate `ActiveFluidType` back (HUD already reads it), or carry the fluid type in the `ServerSpray` RPC.*
- **MP-2 — Sprint and ice fight over `MaxWalkSpeed` from opposite sides.** Sprint writes it client-only (`HoldoverCharacter.cpp:222-236`); ice writes it server-only (`HoldoverHazardVolume.cpp:46`, restore at :76). Remote players rubber-band when sprinting or on ice. On the host the absolute-write vs multiply/divide interaction compounds: enter ice → sprint → leave ice = **permanent 2x walk speed**. *Fix: a replicated speed state applied on server AND owning client (CMC saved-move flag or replicated multiplier); never raw `MaxWalkSpeed` writes from one side.*
- **MP-3 — Client disconnect while possessing the truck destroys the truck for everyone.** `TryEnter` makes the level-placed truck the connection's pawn (`HoldoverDeicingTruck.cpp:121`); no `UnPossessed`/`Destroyed` override on the truck, no `Logout` in `AHoldoverGameMode`. Default controller cleanup destroys the pawn; the occupant's character stays hidden/collisionless forever (:122-123 never undone). *Fix: GameMode `Logout` + truck `UnPossessed`/`EndPlay` evict the occupant and restore the character on both sides; guarantee a level pawn is never a connection's destroyed pawn.*
- **MP-4 — Remote truck occupant's spray ignores the boom.** `SetSprayOrigin(Nozzle)` runs only in server-side `TryEnter` (`HoldoverDeicingTruck.cpp:126`); `SprayOrigin` is Transient/unreplicated (`HoldoverSprayComponent.h:77`); the targeting trace runs on the owning client (cpp:92-97), which falls back to the truck root/rotation. Boom aim does nothing for remote occupants. *Fix: set origin on possession on both sides (PossessedBy + OnRep), or derive nozzle origin whenever the owner is the truck.*
- **MP-5 — Aircraft departure and shift reset never move on clients.** `SetReplicatingMovement(false)` (`HoldoverAircraft.cpp:15`) while the server flies the plane via `AddActorWorldOffset` (:108-113) and resets via `SetActorLocation` (:74). Clients see "DEPARTED" with the plane parked forever; late joiners see every departed plane on the stand. *Fix: `SetReplicatingMovement(true)` or drive the climb-out client-side from the replicated state.*
- **MP-6 — Truck occupancy not replicated.** `OccupantCharacter` is Transient (`HoldoverDeicingTruck.h:129`); prompts are evaluated client-side, so clients see "Press E - Enter Deicing Truck" on an occupied truck and get silently rejected. Server-side `SetActorEnableCollision(false)` on the occupant doesn't replicate either → invisible blocking capsule on clients. *Fix: replicated occupant ref / bOccupied; replicate the collision change.*
- **MP-7 — `ServerSetBoom` is a reliable RPC per frame per held key** (`HoldoverDeicingTruck.cpp:186`, bound to Triggered at :303-306). 120+ reliable RPCs/sec risks reliable-buffer-overflow disconnects; yaw is unclamped and no rate/delta validation. Plain `DOREPLIFETIME` without `COND_SkipOwner` also snaps the predicting owner's boom backwards. *Fix: unreliable + quantized (or send input state, integrate server-side), clamp yaw, `COND_SkipOwner`.*
- **MP-8 — `ServerSpray` trusts client-supplied `DeltaSeconds`** (`HoldoverSprayComponent.cpp:172-188`): only `<= 0` is rejected, so one RPC with dt=1000 cleans/protects a section instantly. Range check is owner-root to target-root vs `SprayRange*2` (=1200uu), which both misses LOS and **falsely rejects legitimate full-extension truck sprays** (nozzle up to 900uu from root + 600uu range). *Fix: clamp dt to ~2x `SprayRequestInterval`; measure from the active spray origin; consider a server re-trace.*
- **MP-9 — Transient input contexts accumulate and are never removed.** Truck adds a fresh priority-100 IMC with 10 new transient actions on every possession (`HoldoverDeicingTruck.cpp:269-301`); character does the same (`HoldoverCharacter.cpp:159-174`); no `RemoveMappingContext` anywhere in the module. After the first truck exit the stale truck context (W/A/S/D/E/LMB) can shadow character input; contexts duplicate per enter/exit cycle. *Fix: persistent input assets (or cached singletons) + explicit remove on unpossess; distinct priorities for truck vs on-foot.*

## B. Uncommitted Phase 7 diff — fix BEFORE committing (P7-1 .. P7-5)

- **P7-1 — The shift-results banner can never appear.** `UHoldoverShiftResultsWidget::NativeTick` sets itself `Collapsed` while the shift runs (`HoldoverPanelWidgets.cpp:165`); a Collapsed UserWidget stops receiving NativeTick (ticked via `SObjectWidget::Tick` from paint), so the first tick hides it permanently and the show-at-shift-end code never runs. The payoff screen of the whole loop never shows. *Fix: parent `UHoldoverHUDWidget` drives the child's visibility (or use `Hidden`, or event-driven via `OnRep_Shift`).* Note: the checklist item for this is still unchecked — the PIE evidence did not cover it.
- **P7-2 — Spray-hiss loop leaks on truck exit.** `ServerExit_Implementation` re-possesses the character at `HoldoverDeicingTruck.cpp:151` **before** `SetSpraying(false)` at :161; the hiss stop branch is gated on `IsLocallyControlled()` (`HoldoverSprayComponent.cpp:27`), false by then → hiss loops forever. Remote clients never even run the stop path. *Fix: stop the hiss unconditionally in `SetSpraying(false)`; also stop spraying in `UnPossessed`/`EndPlay`.*
- **P7-3 — Urgency colour coding regressed in the canvas→UMG rewrite.** Old DrawHUD coloured the holdover line green/yellow (<30s)/red (expired); the new departure board sets text only (`HoldoverPanelWidgets.cpp:79`), fixed white. The checklist item "expired holdover turns red" can no longer pass. *Fix: restore the colour ramp on the board; consider a pulse + audio layer near expiry.*
- **P7-4 — `detrend()` in `Tools/build_placeholder_audio.py:48` is algebraically wrong** (`drift` reduces to `samples[-1]`; last sample becomes 0 but the first stays nonzero), so the hiss/wind "seamless" loops still click at the seam. *Fix: subtract `samples[0] + (samples[-1]-samples[0]) * i/(n-1)`.*
- **P7-5 — All audio is local-only unspatialized 2D.** Hiss/collision cues are gated on `IsLocallyControlled`; `bSpraying` is never replicated — teammates' sprays, collisions and jet-blast launches are silent and invisible to other players. In this genre, hearing your coworker get launched *is* the content. *Fix (can land with Phase 8): replicated cosmetic spray state + spatialized cues; cache sounds (TMap/TSoftObjectPtr data asset) instead of `LoadObject` by path per play (`HoldoverAudioLibrary.cpp:12`); plan the wind loop via `PawnClientRestart`, keep a handle, scale with weather.*

## C. Simulation & tuning defects (SIM-1 .. SIM-5)

- **SIM-1 — Weather never resets and ramps monotonically to permanent max** (verified). `Tick` ramps +0.01/s clamped to 1.0 (`HoldoverGameState.cpp:109-121`); `StartShift`/`RestartShift` never touch it; `SetWeatherSeverity` has zero call sites. Severity pins at 1.0 after ~100s; every later shift plays at max difficulty. *Fix: reset/randomize per shift; squalls and lulls instead of a one-way ramp.*
- **SIM-2 — Penalty-free abort dominates the expiry mechanic.** At threshold 95 (`HoldoverSurfaceSection.h:39`) and 2%/s*weather degradation, protection falls below threshold ~2.5s after holdover start (severity 1); the `HoldoverActive` branch aborts to `Incomplete` with zero cost (`HoldoverAircraft.cpp:238-243`) while expiry (which dumps all protection) is practically unreachable. Optimal play is to ignore the clock and top up last-moment. *Fix: make aborts cost something, or pause/slow degradation during an active holdover so expiry is the clock players actually fight.*
- **SIM-3 — Cleanliness never decreases.** No code path lowers `CleanlinessPercent` except shift reset; snow never re-contaminates, so Type I is a one-shot task and Type IV protects nothing physical — it is only a gate flag. *Fix: precipitation lowers cleanliness on unprotected sections.*
- **SIM-4 — Deductions/penalties are cosmetic.** `bShiftPassed = OnTimeDepartures >= Quota` only; Money and Deductions are never netted, compared or persisted (`HoldoverGameState.cpp:56`, zeroed each shift at :28). "Late departure" can also only fire after `EndShift` has already broadcast the final report (`HoldoverAircraft.cpp:46` + `HoldoverGameState.cpp:41-46`). *Fix: net pay, penalties that can fail a shift, per-aircraft deadlines so lateness exists in play.*
- **SIM-5 — Section registration is a one-shot radius gather** (`HoldoverAircraft.cpp:92`; the header comment claims sections self-register but `HoldoverSurfaceSection` has no BeginPlay). Two aircraft with overlapping 1500uu radii would both claim the same sections. Blocks multi-plane shifts; quota > 1 is already unwinnable with one plane. *Fix: explicit section→aircraft ownership (attach/spawn-owned or an editable aircraft ref).*

## D. Design gaps (DES-1 .. DES-6) — verified against plan vs build

- **DES-1 — One plane, quota 1, 2-minute shift** (`HoldoverGameMode.h:24-27`; BP game mode overrides neither — binary-checked). The plan's own first-shift spec is 2 aircraft / 8 min / quota 2, and GameMode's assigned "spawn/queue aircraft" job is unimplemented (`BeginPlay` calls `StartShift` once, never spawns). Triage between competing clocks IS the game and cannot exist with one clock. **Highest-value design change.**
- **DES-2 — No inter-player dependency.** Everyone carries both fluids/tanks, refills are free+instant, anyone can request clearance; `AHoldoverPlayerState` (in the plan's architecture table) does not exist — zero `PlayerState` matches in Source. Nothing requires, measures, or notices a second player. *Fix: PlayerState + attribution ("Deductions: Dan -$75"), then one-tank-per-player (choose Type I or IV at the refill station) to force the clean→protect relay.*
- **DES-3 — Comedy pitched everywhere, implemented almost nowhere.** All 10 `AddDispatch` call sites emit fixed utilitarian status strings; no line pool, no reactivity, no blame. The plan's "brief, funny stumble" on ice shipped as a silent speed halving; one `LaunchCharacter` is the entire physical-comedy budget. *Fix: a 60-100 line reactive dispatcher bank keyed to event + repetition + blame, in the RESTRUCTURED voice; a real slip/stumble; knockable props.*
- **DES-4 — No chaos generators / session shape.** No weather events, equipment failures, dispatcher curveballs, or randomness; `RestartShift` replays identical settings. *Fix: `AHoldoverShiftData` shift profiles (night 1 easy → night 5 blizzard) + data-driven shift events; a running company ledger between shifts.*
- **DES-5 — Data-asset mandate unmet.** Tuning is scattered `EditAnywhere` across 4+ classes ("data-asset-ise later" is in the headers); the plan mandates `UHoldoverFluidData`/`AHoldoverShiftData`. Blocks the tuning/content pass. (SIM-2's numbers fighting each other is the symptom.)
- **DES-6 — The 30-day plan schedules zero fun-finding.** Phases 8-10 are art/netcode/packaging; the only playtest is days 28-29 after freeze. The team is running ~7x ahead of the sprint table on systems — spend the surplus on a dedicated playtest-iterate phase on DES-1..DES-4 with one gate: did anyone laugh unprompted; did players talk to coordinate.

## E. Tests, tooling, process (PROC-1 .. PROC-6)

- **PROC-1 — Zero automated multiplayer coverage** (verified). All 6 tests are `NewObject` on the transient package — no world, no NetDriver, no RPC, no replication. The riskiest half of the product is untested; that is exactly why MP-1..MP-9 survived to Phase 7. *Fix: world-based functional tests (PIE/Gauntlet) for ServerSpray rejection, replicated section state, host/client score agreement; make "play as client + net emulation (PktLag=120 PktLoss=5)" the manual checklist.*
- **PROC-2 — MCP plugins without `TargetAllowList` — downgraded.** The claim that `ModelContextProtocol`/`ToolsetRegistry`/`AllToolsets`/`PythonScriptPlugin` (Holdover.uproject:34-49) would be staged into a shipped Steam build was **refuted** on verification against the UE 5.8 plugin sources. Still: add `"TargetAllowList": ["Editor"]` (as `ModelingToolsEditorMode` already has), make MCP auto-start a per-developer opt-in instead of committed config (`Config/DefaultEditorPerProjectUserSettings.ini`), and do an early packaging dry run rather than waiting for Phase 10.
- **PROC-3 — TEST_CHECKLIST overstates coverage** (verified). "Penalties applied once ... test PASS" — no test touches `RegisterPenalty`/jet blast (and `OnOverlapBegin` has no once/cooldown gate, so the penalty is NOT applied once); "Server validates spray range — PASS" while no test calls `ServerSpray`. *Fix: downgrade to match reality; re-encode the file to UTF-8 (it contains raw cp1252 bytes).*
- **PROC-4 — No headless test runner, no CI.** Every "all tests PASS" ran via MCP inside a live editor. *Fix: commit `Tools/run_tests.ps1` wrapping `UnrealEditor-Cmd -ExecCmds="Automation RunTests Holdover" -nullrhi -unattended` with exit-code checks; CI on the PR workflow the README already mandates.*
- **PROC-5 — The greybox builder deletes hand-placed work** (`Tools/build_ramp_greybox.py:54-59` clears every non-system actor). Incompatible with the Phase 8 art pass as designed. *Fix before Phase 8: script-owned sublevel/data layer vs human-owned level, or freeze the script.*
- **PROC-6 — Packaging debt:** default game mode is the template BP kept alive by CoreRedirects, `ServerDefaultMap` is `/Engine/Maps/Entry`, splitscreen on, AndroidFileServer enabled with a committed token in a PC-only project, OnlineSubsystemSteam not started (`Holdover.Build.cs:34-37` still template stubs), stale Unity-era `.vscode/settings.json`. None urgent; all cheap now, expensive at Phase 10.

Lower-severity items worth a sweep when touching these files: stale interaction prompt while in the truck; truck has no camera (occupant's view is inside the greybox body — add a basket/chase spring arm); jet blast has no per-player cooldown (griefable team penalty) and is unpredicted (reads as a teleport, not a gag); departure board picks an arbitrary aircraft via per-tick `TActorIterator`; host vs client beep-count mismatch (documented); test-interactable uses a class-static toggle and server-only cosmetics (do not copy the pattern); first-person-template residue (mobile touch stack, `LogTemplateCharacter`, template strings).
